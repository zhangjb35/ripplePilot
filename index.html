What ripplePilot adds

Not another reading of the literature — infrastructure that keeps the literature queryable, checkable and current.

01

Consensus becomes machine‑checkable

Field‑wide agreements on what counts as a ripple — band, filter, threshold, artefact rejection — stop being prose and become queryable attributes attached to each node. Divergence between labs becomes visible instead of buried in methods sections.

02

Claims carry their provenance

Because every finding is linked to the specific dataset and the specific code that produced it, a statement can be followed back to its evidence — and re-checked when the data or the pipeline changes.

03

Cross‑species and cross‑method links

Rodent to human translation, ripples to replay, decoded content to recorded ripples — these bridges are usually argued in text. Here papers, datasets and code sit in one indexable field, so the bridges can be queried and gaps become findable rather than merely acknowledged.

04

A living map, not a snapshot

A review is fixed at publication. ripplePilot keeps accumulating papers, datasets and code, so the same question can be re‑asked months later and answered against the current state of the field.

Any research agent can query it — and the human stays in the loop.

One MCP endpoint, four tools — an agent can search, retrieve and cite the evidence directly, with no re-reading and no re-keying. What comes back is not a verdict: every claim carries the dataset and the code behind it, so a researcher can check the provenance and decide what to cite. The question is yours, and so is the conclusion.
